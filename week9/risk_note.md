**Who wrote it:** the claims platform team, not us — we run their code (`mcp_servers/claims_system_server.py`) as a child process of our agent, it declares no version (`serverInfo.version` is `""` in wire.json), and its tool descriptions go into our model's prompt verbatim.
**What it can reach:** every claim record and the full adjuster note history for any claim number it is asked about — no per-claim scoping — plus our filesystem with the agent's own OS permissions, because stdio servers run as us.
**What it logs:** one line per tools/call to `week9/logs/claims_server.log` (timestamp, tool, claim number — a record of which claims were looked up, never the note text); it does not log who asked, so the log cannot attribute a lookup to a user.
**What a stolen token could do:** read the notes on every open claim — redaction runs inside the same server, so the credential, not our agent, decides what leaves — and nothing scopes it to the adjuster-notes tool alone.
**Ship or don't:** don't ship as-is — ship only behind a gateway that pins the server build, scopes the token per tool (status yes, notes only for the claim being triaged) and writes caller + tool + claim number to one audit line.
